## Ask AI

Model features are off until an admin [connects a model](/admin/ai/). With them off, no AI control shows anywhere. When they are on, you may see:

- **Explain more** on a failure: the rules-based diagnosis of a failed app or job is always there; this asks the model to explain it further. The answer is labelled as generated by AI from app output: your app's log is sent, and anyone your app serves can put text in it, so read the answer with care. Links are removed from it, and it proposes no change that only log lines back; any change it proposes waits for you to approve it. **What will be sent** shows the exact text to the app's owner only; a platform admin explaining your app sees neither that text nor how many values were hidden, and your secrets are sent to the model without their names.
- **Describe it** on New app: describe the app you want in plain words and the model fills in the form. Nothing is created until you press **Create app**.
- **Suggestions** in New app's **Describe it** box, when your admin gives coding agents a model: as you type, after a short pause, whole descriptions that complete what you typed appear under the box. Up and Down move through them, Enter or Tab (or a click) puts one in the box, Escape closes them. They use your templates and the names of the files and folders at the top of your home folder, never what is in them, and count against your daily allowance.
- **Ask AI** in the search palette (Cmd+K or Ctrl+K): ask for a change. The answer is a plan you approve, or a draft that opens New app.
- **Ask about this cluster** in the palette, for platform admins: questions about the cluster report. The answer cites its rows and changes nothing.

Each person has a daily allowance of model tokens (per UTC day). Every token a call uses counts, including a retried answer. When it is used up, Javo says when it resets. Up to 20 proposed changes may wait for your approval at once (your admin [sets the limit](/admin/limits/)); approve or reject some to propose more.

## Build with pi

When your admin gives coding agents a model, or you stored your own key in **Settings > Secrets > AI agent**, the search palette offers **Build with pi: <your words>**. It starts a new pi app named after your request, gives pi your request as its first prompt, and opens the app's page; **Open** shows pi at work in its terminal. pi starts in your home folder, or in the folder your request names (such as `~/projects/sales-dashboard`) when it exists. It can write code there, deploy it as an app or a job, wait for it to run and read the startup logs when it fails. It cannot give an app secrets or API access, share it, or touch an app or job that holds a secret: it asks you to do that, or proposes a change for you to approve. The first prompt runs only on the app's first start.

## Coding agents (MCP)

Agents such as Claude Code or Cursor can work with Javo through its MCP endpoint at `/mcp` on the Javo address. MCP needs no model and is on unless your admin turned it off.

1. Create a [personal API token](/using/api/#api-tokens) with the **Propose** scope. A read-and-write token would also work, but then the agent could skip MCP and make any change directly through the API, so the approval step would protect nothing.
2. Configure the agent with the MCP address, `https://<javo address>/mcp`, and the token as a bearer token.

An agent can read what you can read through API routes that answer JSON. Streams and downloads (log streams, job run logs, raw files, the apps export) are not offered as tools, and an answer larger than 1 MiB is cut off with an error; use the API directly for those. It can only **propose** changes: each proposal is a plan that waits for you to approve or reject it in the browser, at a link the agent shows you. Approving needs your browser session; a token alone can never approve. Plans expire after 10 minutes unless your admin changed it.
